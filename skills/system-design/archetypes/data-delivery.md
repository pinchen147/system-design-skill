# Data delivery archetypes

Selected from the router for [SKILL.md](../SKILL.md). Reusable mechanisms and decision ladders remain in [HEURISTICS.md](../HEURISTICS.md).

## Media pipeline and edge delivery
- **Shape**: upload-transcode-stream; reads greatly outnumber writes; cost is a first-class constraint.
- **Match when** bytes are large, immutable once published, and the bill is dominated by egress. **Not when** the payload is small or mutable — that is a metadata problem with a cache in front of it.
- **Moves**: pre-signed multipart uploads—bytes go client→blob directly, each part checksummed and resumable; transcoding as a replayable DAG over few-second chunks; adaptive bitrate via segmented HLS/DASH manifests; CDN for the popular long tail, origin/on-demand encoding for the rest; fire-and-forget progress writes; signed URLs + DRM.
- **Staff gate**: compare egress, storage, and transcode dollars before service topology. State upload finalization verified against the object store's own part list rather than the client's word, idempotent job identity, partial-transcode cleanup, manifest publication atomicity, multi-CDN failover, and the measured $/GB gate for owned edge capacity.
- **Numbers anchor**: an illustrative 5M DAU × 30 MB new media/user/day is 150 TB/day; calculate delivered GB × the contracted CDN rate before changing topology rather than importing a universal dollar estimate.
- **Anti-gate**: while measured annual egress and transcode savings remain below the incremental engineering and operations cost of owned delivery, one origin behind a commodity CDN is the design.
- **Cases**: video platforms, podcast and audio hosting, image pipelines, game asset delivery, model weight distribution.

## Immutable artifact distribution
- **Shape**: a version identifier always means the same bytes, forever, and whatever is running can be traced to the source and the process that produced it.
- **Match when** something built once is consumed many times by parties who must verify and reproduce it — packages, container images, model weights, deployment bundles, firmware. **Not when** the name is supposed to track changing content: a document namespace, a user's file tree, a configuration value whose whole purpose is to change under a stable key. That is a mutable namespace with versions, and content addressing there fights the requirement.
- **Minimum state**: a content digest per artifact, an immutable mapping from version identifier to digest, and a signed statement binding the digest to its inputs and its builder. Tags are a separate, mutable, deliberately untrusted layer above that.
- **Moves**: caching and edge placement are ladders in [HEURISTICS.md](../HEURISTICS.md), and content addressing collapses them — an artifact named by its own digest is infinitely cacheable, deduplicates across every consumer, and needs no invalidation. Layer the artifact so an unchanged part is never re-transferred. Verify digest and signature at the consumer, not only at the registry. Expire the freshness metadata so replaying yesterday's still-valid index is detectable. Withdrawal retracts a pointer; it never mutates bytes.
- **The dial**: verification strictness against release friction. Threshold signing and provenance make a compromise survivable and make every emergency release slower; the dial is set by who may publish and what a bad artifact costs downstream.
- **Buy gate**: managed registries already ship content addressing, replication, retention, scanning, and signing. Building distribution must beat that on a stated requirement — air-gapped zones, an artifact size or fan-out it prices badly, a provenance policy it cannot express — not on preference.
- **Staff gate**: state what rollback means when the previous artifact is incompatible with already-migrated data — that is the rollback that actually fails. Name the retraction path (yank, deprecate, delete) and what happens to consumers who already resolved the version. Say who may sign, how a signing key rotates without a flag day, and how a consumer offline for a month catches up safely. A mutable tag is a convenience, not a version: nothing in the deployment flow may resolve one at run time.
- **Numbers anchor**: registry policy is what makes the invariant real, not storage. A published version may be withdrawn only inside a 72-hour window and only when nothing depends on it; past that it takes no dependents, under 300 weekly downloads, and a single owner — and once a version identifier has been used it can never be reused, even after withdrawal. That single rule is what makes a lockfile mean anything.
- **Anti-gate**: one team, one target, artifacts built and consumed inside one trust boundary — a versioned tag in one registry and a rollback runbook. Threshold signing roots, transparency logs, and provenance attestation are for artifacts crossing a trust boundary and cost real release velocity.
- **Breaks first**: not the distribution. The rollback, on the day a bad release ships — the artifact reverts cleanly and the migrated data does not.
- **Cases**: container registries, language package registries, model and dataset registries, OS update channels, progressive deployment controllers.
